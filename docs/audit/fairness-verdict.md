# 벤치마크 공정성 최종 판정

검토 대상: `bench/bench.mjs`와 23개 벤치마크 결과(2026-10-12~13), 그리고 이를 분석한 네 개의 감사 보고서(`.omo/audit/contamination.md`, `metrics.md`, `order.md`, `variance.md`). 본 문서의 모든 판정 근거는 독립 검증 문서 `.omo/audit/verify.md`(2026-10-13)에서 **CONFIRMED**로 표시된 주장만 사용한다.

## 1. 판정

**판정: 불공정. 이 벤치마크는 cold와 trail-off를 공정하게 비교했다고 인정할 수 없다.**

다만 판정의 범위를 정확히 한정한다. verify.md의 독립 검증이 확인한 것은 두 가지다. 첫째, trail-off가 cold보다 다른, 잠재적으로 유리한 시작 조건을 받을 수 있는 비대칭 메커니즘이 소스 코드에 실재한다. 둘째, 측정된 trail-off 우위가 그 메커니즘 때문이라는 인과 증거는 없고, 관측된 결과는 런 간 변동성과도 양립한다(verify.md "Final mechanism adjudication", "Answer").

즉 "공정한 비교였고 차이는 단순 분산이다"도, "trail-off가 입증된 부정한 이득을 얻었다"도 성립하지 않는다. 성립하는 결론은 하나다. **비교 설계가 불공정하므로 현재 수치로 cold 대비 trail-off의 우열을 논할 수 없으며, 재측정이 필요하다.**

## 2. trail-off가 4개 작업 중 3개에서 cold를 앞선 이유(확인된 메커니즘)

먼저 관측 사실부터 정리한다. 2026-10-13 `03-*` 런 8개(4개 작업)에서 첫 REPL 호출 기준 cold 대비 off의 작업 평균 차이는 tracking +89.724ms(+1.846%), Scholar +718.724ms(+60.923%), Naver +111.247ms(+5.154%), YouTube -26.032ms(-0.915%)로, **cold가 더 느린 작업이 4개 중 3개**다(verify.md O3). 다만 전체 wall time 기준으로는 8쌍이 4승 4패로 갈린다(verify.md V8).

왜 이런 결과가 나왔는가. verify.md가 CONFIRMED로 확인한 범위에서 답은 두 부분이다.

### 확인된 것: trail-off에 유리할 수 있는 비대칭 메커니즘이 존재한다

- **브라우저/프로파일 상태의 순서 이월**(verify.md 최종 판정 1항). trail-off는 항상 두 번의 앞선 작업 실행 뒤에 돌며, 루트 페이지 예열 지시가 같아도 깊은 페이지 캐시와 실제 수행 작업은 같지 않다(O5에서 첫 호출이 서로 다른 작업을 수행함이 확인됨). 따라서 나중 암이 이전 깊은 페이지 방문의 상태를 물려받을 수 있고, 이 설계는 무작위화·격리된 비교가 아니다.
- **생존 컨텍스트의 변화**(최종 판정 2항, C7). cold와 off 사이의 전역 수집/증류가 다른 호스트 스킬을 바꿀 수 있고, `HOSTS`에 없는 관련 호스트가 작업 호스트로 가는 경로를 유지할 수 있다(`src/core.mjs:539-555`). Naver off 로그에서 다른 호스트의 Trail 스킬을 실제로 읽은 사례가 확인됐다(`S(2026-10-12_JzJhk64Sq6YYAH0S):44-45`).
- **과거 순서 버그의 조건부 메커니즘**(최종 판정 3항, C6). `off` 후 `forget` 순서면 `syncAsideMemory`가 `enabled`/`emit` 플래그와 무관하게 관리 블록을 다시 써서, cold와 off가 서로 다른 정리 순서를 쓰는 경우 off 쪽 컨텍스트가 더 작아질 수 있다. 현재 소스는 두 암 모두 `forget` 후 `off`이므로 현재 버전의 잔존 비대칭은 아니며, 어떤 과거 결과 파일에 귀속되는지도 입증되지 않았다.

### 확인된 것: 인과는 입증되지 않았고 결과는 런 간 변동성과 양립한다

- 위 메커니즘들은 **방향성 편향이 가능한 기회**로 확인됐을 뿐, 측정된 우위를 일으킨 **원인으로는 입증되지 않았다**(verify.md "Result", 최종 판정 1~2항).
- 반대 방향 오염도 실측됐다. cold r6이 Aside 메모리에서 쿠팡 주문 경로와 답을 조회해 11회 호출·51.327초로 끝냈고, 같은 시나리오의 cold r7은 선택자를 반복 시도하며 23회·108.705초가 걸렸다(최종 판정 4~5항). 같은 cold 조건에서 호출 수가 2.09배 차이 나는 것은 행동 변동이 크다는 직접 증거다.
- 오염이 없다는 소극적 증거도 있다: 24개 `03-*` 로그에서 `trail-*` 파일, `MEMORY.md`, Trail JSON 저장소를 명시적으로 읽은 기록은 없었다(다만 자동 프롬프트 주입은 배제 못 함).
- 정정된 집계 기준 trail-off는 전체 23쌍에서 wall time 14승, REPL 10승(무 4), tokens 10승이다. 이는 "일관된 우위"가 아니며 작업·지표별로 부호가 갈린다(V8).

**종합**: trail-off가 3/4 작업에서 앞선 것은 확인됐지만, 그 원인은 "고정 순서와 잔존 컨텍스트 변화라는 불공정 설계가 만들었을 가능성이 확인된 상태에서, 실제로 그렇게 만들었는지는 미입증"이다. 관측값은 모델/행동 변동만으로도 설명 가능하다.

## 3. 한 줄 결론

**이 벤치마크는 불공정하다. trail-off가 유리할 수 있는 구조적 결함이 확인됐으므로 현재 수치는 cold 대비 우열의 근거가 될 수 없고, 실행 순서 무작위화·브라우저 상태 초기화·정리 검증을 갖춘 설계로 재측정해야 한다.**
