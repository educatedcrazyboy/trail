# Aside 문의용: 벤치마크 격리 인터페이스 요구사항

상태: 전달용 초안. 문의를 발송하지 않았으며, 아래 기능의 존재를 가정하지 않는다.

## 문의 배경

Trail 유무만 다르게 한 비교가 필요하다. 일반 사용자 계정의 기존 기억,
이전 실행의 브라우저 상태, 측정 중 새로 생긴 기억이 결과에 영향을 주면
비교를 시작해서는 안 된다. 현재 하네스는 이를 확인할 수 없어 실벤치를
모델 호출 전에 차단한다.

공식 문서 위치(사용자 제공): `https://docs.aside.com/help/memory`.
2026-10-14 사용자 조사에 따르면 메모리 끄기를 새 기억 생성 중단으로
설명하며 기존 검색·자동 주입 차단은 명시하지 않는다. 이 세션의 웹 조회는
본문을 반환하지 않아 해당 문서 내용을 독립 확인하지 못했다.
실제 UI의 Enable memories 설명도 "Generate new memories from chats"다.

## Aside 측에 확인할 계약

아래 명칭은 요구사항 식별자이지, 존재하는 CLI 옵션이나 API 이름이 아니다.

| 식별자 | 필요한 제어 | 반환·기록되어야 하는 증거 |
| --- | --- | --- |
| BROWSER | 벤치 전용의 독립 브라우저 컨텍스트 생성·종료. 각 arm의 초기 상태가 동등해야 함 | 실제 컨텍스트 ID, 소유 실행 ID, 프로필·스토리지 범위, 종료 확인 |
| AUTH | 전용 컨텍스트에 동일 계정으로 별도 로그인하는 지원 절차 | 로그인 여부·동일성의 비밀값 없는 확인. 메인 프로필 복제나 쿠키 삭제 불필요 |
| READ | 세션별 기존 memory_search, episodic/site memory, 자동 기억 주입 차단 또는 독립 namespace | 유효 설정과 적용 범위, 차단된 호출의 명시적 오류, 초기 namespace 증거 |
| WRITE | 측정 중 기억 생성·요약·indexing·background ingestion 차단 또는 실행별 저장소 제한 | 적용된 설정, 종료 후 저장소 변경 내역, 백그라운드 작업 범위 |
| CONTEXT | 숨은 프롬프트를 포함한 입력 구성의 재현 가능성. 개인정보·비밀은 제외 | 구성 요소별 content hash·바이트 수, skill inventory, model/effort |
| TREATMENT | 동일한 동결 학습 산출물을 trail-on에만 제공 | 학습 입력·산출물 hash, 다른 두 arm에서 해당 내용이 없다는 증거 |
| SESSION | CLI 실행과 실제 세션·브라우저·계정 namespace의 정확한 결합 | 단일 세션 ID와 구조화된 시작·완료·실패 이벤트 |
| MODEL | 요청한 provider/model/effort와 실제 실행 설정 일치 검증 | 요청·해결된 모델 ID, fallback 여부와 이유, 불일치 시 요청 전 거부 |
| LIFECYCLE | 소유 자원만 정리하고 오류 시에도 실행 종료 | 종료·정리 receipt, 취소·강제 종료 시의 동작 |

프로필 선택과 계정 선택이 각각 어떤 범위의 메모리·skills·history를
공유하는지도 명시해 달라. 메모리 생성 OFF와 검색·주입 OFF는 별개로 답변이 필요하다.
기능이 없다면 지원되지 않는다고 명확히 답변해 달라.

## 통합 수락 시나리오

실제 지원 API가 확인된 뒤 아래 ID에 해당하는 호출과 응답을 테스트로 고정한다.
아직 알 수 없는 호출 이름을 만들어 구현하지 않는다.

1. **메모리 read 차단:** 전용 seed namespace에 예측 불가능한 canary를 넣는다.
   격리 namespace의 검색 결과와 입력 구성에 그 canary가 없고, 금지된
   검색 호출은 명시적 거부를 반환해야 PASS다. 정답을 못 맞혔다는 것만으로
   주입 부재를 추정하지 않는다.
2. **write 차단:** 전용 실행 전후 memory/skill inventory hash를 비교한다.
   허용한 세션 로그를 제외한 변경이 없고, 종료 후 background 작업도
   같은 범위를 지켜야 PASS다.
3. **브라우저 교차오염:** 전용 arm A의 테스트 origin에 cookie·localStorage·
   IndexedDB·cache canary를 만든다. 독립 arm B에서 모두 관찰되지 않고,
   B의 동일 origin 초기 상태가 baseline과 같아야 PASS다. 메인 프로필은 사용하지 않는다.
4. **처치 단일 차이:** 동결 training artifact와 model/effort는 동일하게
   고정한다. arm별 입력 구성의 차이가 허용된 Trail 처치에만 한정되어야 PASS다.
5. **실패 시 중단:** 격리 기능 미지원·설정 누락·API 실패·ID 불일치이면
   모델 요청 수가 0이어야 PASS다. 자기신고 JSON이나 환경변수로 우회할 수 없어야 한다.
6. **수명 종료:** 생성한 컨텍스트와 소유 임시 저장소만 제거되고 사용자
   프로필은 바뀌지 않아야 PASS다.

위 검증을 통과하기 전에는 로그인 기반 기존 4태스크 실벤치를 재개하지 않는다.
통과 뒤에도 순서 counterbalance와 반복 실행으로 변동성을 보고해야 하며,
그것이 격리 증거를 대신하지 않는다.
