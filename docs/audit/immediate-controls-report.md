# 즉시 가능한 10개 작업 결과

2026-10-15. 실행 범위는 로컬 통제·기존 기록 분석이다.
**실제 Aside 격리 환경 완성이나 성능 우위의 증거는 아니다.**
실벤치·모델 요청은 재개하지 않았고 사용자 프로필도 변경하지 않았다.
개발 에이전트의 추론 비용은 별도로 발생했다.

## 1. 핵심 발견

40개 JSON 결과와 Markdown 보고서, 총 41개 보관 파일에 연결된
**120개 Aside 세션**을 모두 찾아 분석했다. 누락·모호한 매칭은 0개다.
새 감사기가 처음에는 결과 JSON의 짧은 세션 ID를 놓쳐 3개만 찾았으나,
리드가 r7 cold 누락을 재현한 뒤 고쳤다. 이전 3개 집계는 폐기된 결론이다.

| 보존된 스냅샷 범위 | 기록 totalTokens 합계 | 그중 cacheRead | 기록 비용 추정 USD |
| --- | ---: | ---: | ---: |
| Aside 과거 120세션 | 135,443,827 | 116,406,231 | 2.143249039 |
| Senpi 부모 대화 전체 스냅샷 | 424,409,972 | 401,849,921 | 16.2136384 |
| 찾을 수 있었던 자식 로그 3개 | 1,482,784 | 1,390,720 | 2.56036 |

**이 표는 이번 요청만의 소비량도, 청구서도 아니다.** 부모 대화는 여러 날의
이력을 포함하며 계속 커진다. totalTokens는 매 요청의 긴 문맥과 캐시 읽기를
반복 합산한 처리량이다. 비용 열도 로그 작성기의 가격 추정이고 실제 과금은
확인할 수 없다. 찾지 못한 자식 로그 두 개는 0이 아니라 미확인이다.
원시 로그와 native DAG 통계도 겹칠 수 있어 합산하지 않았다.

| 세션 | 도구 호출 | 기록 처리량 | cacheRead | 종료 |

첫 세션의 동일 도구·인자 반복 초과분은 11회다. 따라서 “동일 호출만 차단”해도
206회의 긴 탐색 전체를 막지는 못한다. 모든 호출을 세는 실행기 한도가 필요하다.
두 번째 세션도 REPL만 세면 bash 42회가 빠진다.

전체 Aside 기록에는 1,543회 호출, 동일 인자 반복 초과분 112회, 오류 결과
173개가 있다. 부모 대화에는 3,199회 호출, 동일 인자 반복 초과분 1,542회가
있다. 동일 인자는 검증 가능한 사실이지만 모든 반복이 불필요했다거나
이들만 제거하면 특정 금액을 절약한다는 인과 결론은 내리지 않는다.

**쉬운 설명:** 도구를 한 번 쓸 때 새 질문 몇 글자만 읽는 것이 아니라,
길어진 대화·참고자료도 다시 처리한다. 긴 문맥으로 수백 번 움직이면 합계가
커진다. 캐시가 그 비용을 줄일 수는 있지만, 처리 토큰 숫자를 실제 결제액으로
그대로 바꿀 수는 없다.

## 3. 강제 제한의 정확한 범위

**새 한도는 새 로컬 HTTP 모의 실행기의 요청에만 강제된다.**
설치된 Senpi의 task 엔진, 현재 코딩 대화 전체, 실제 Aside 모델 생성에
하드캡을 설치한 것이 아니다. 그 경로의 강제 제어 인터페이스를 확보하지
않은 상태에서 해결됐다고 말하지 않는다. 유료 실벤치는 별도의 기존 gate가
실행 전에 계속 거부한다.

기본 한도는 arm당 12회·전체 260회, 응답당 65,536바이트,
arm당 1,500ms·전체 60,000ms다. 관측 토큰 한도는 arm당 1,000이며
모의 서버가 제공하는 합성 계측이다. 이미 진행 중인 응답의 초과를 미리
막을 수는 없고, 관측 후 다음 호출을 막는다.

**쉬운 설명:** 모형 시험기의 차단기는 설치·검증했다. 실제 유료 모델과
개발 에이전트 전체의 전기 계량기에 차단기를 단 것은 아니다. 따라서 이번
작업 자체가 무료였다거나 앞으로 모든 에이전트 비용이 제한됐다고 할 수 없다.

## 4. 직접 실행한 검증

- 리드가 source·테스트·fixture·프로토콜을 읽고 원래 요구와 양방향 대조했다.
- lifecycle 학습 준비: 실제 CLI 성공, 18 arm. 올바른 외부 pin 성공,
  잘못된 pin은 실제 exit 2. coherent replacement는 기존 pin으로 거부.
- local HTTP: 18 arm·72 과업 성공. 13가지 fault를 각각 CLI로 주입해
  전부 exit 2 및 실패 판정 확인. 출력 경로 재사용은 파일을 바꾸지 않고 거부.
- oracle 반례: `year=20240`에서 `2024`를 오통과하던 것을 실패로 재현했고,
  수정 후 같은 직접 호출은 false, 정확한 `year=2024`는 true.
- 전체 감사 CLI: 120개 세션, 누락·모호 매칭 0. 보존 JSON hash와
  불변 Aside 집계가 직접 재실행 결과와 일치.
- `node --test test/*.test.mjs`: **76 PASS, 0 FAIL, 0 SKIP, exit 0**.
  기존 44개를 보존하고 준비 3개·감사 12개·local 17개를 추가했다.
- 네 변경 모듈의 `node --check`도 통과했다. LSP 서버는 설치되어 있지
  않아 진단은 실행하지 못했고 의존성을 추가하지 않았다.

리드 원시 실행 요약·hash·실제 종료값·정리 증거는
`followup-lead-qa.md`에 있다. 자동 생성 before/after 파일은 재실행마다
지정한 새 출력 디렉토리에 생성된다.

기존 package test 스크립트의 `node --test test/`는 현재 Node 26에서
디렉토리 해석 오류가 보고됐다. 이번 검증은 모든 명명된 테스트를 펼치는
위 glob 명령을 사용했다. 이 작업과 무관한 스크립트는 수정하지 않았다.

## 6. 자기 검토와 남은 경계

HEAVY 분류는 새 실행기 경계와 파일 무결성 검사가 있으므로 유지했다.
별도 ulw-plan을 요청받지 않아 추가 reviewer loop 대신 리드 자기 검토를
기록한다. 테스트 통과만으로 끝내지 않고 각 CLI를 직접 실행했다.
단순 파일 분할 외 일반화 프레임워크·외부 의존성은 추가하지 않았다.

프로토콜과 실행기 모두를 함께 바꾸는 공격은 내부 hash만으로 방지하지
못한다. 외부 manifest pin도 별도 보관한 값의 신뢰성까지 만들어주지는 않는다.
과거 prose 답변을 이 새 모의 채점기에 넣어 의미적 성공으로 복원하지 않았다.
모의 shortcut은 실제 Trail 출력이 아니며 24 대 72라는 호출 수를 Trail
성능 개선으로 해석하지 않는다.

실제 Aside 브라우저·계정 기억·자동 주입 격리는 계속 미검증이다.
공정한 실벤치를 실행할 수 있다는 판정과 새 성능 점수는 없다.
